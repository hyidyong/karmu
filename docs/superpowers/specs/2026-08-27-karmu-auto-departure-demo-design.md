# Karmu 자동 출발·계명대 데모 확장 설계

## 목적

사용자가 도착 시각을 직접 입력하지 않고 목적지만 선택한 뒤 `지금 출발`을 누르면, 현재 위치에서 목적지까지의 실제 도로 이동시간을 계산하고 예상 도착 시점의 학생 주차장 혼잡도와 추천 순위를 보여준다. Google Routes API나 위치 권한을 사용할 수 없는 발표 환경에서도 동일한 클릭 흐름이 데모 추정값으로 끝까지 동작해야 한다.

## 범위

이번 변경에 포함한다.

- 브라우저 현재 위치 권한 요청
- Google Routes API 기반 자동차 이동시간 계산
- Google 호출 실패 시 계명대 인근 고정 출발지 기반 폴백
- 예상 도착 시각에 따른 주차장별 잔여면 예측
- 목적지 건물별 도보거리와 학생 이용 권한을 반영한 추천
- 계명대학교 성서캠퍼스 건물·주차장·시간대별 더미 데이터 확장
- 동문·남문 학생주차장을 핵심 추천 대상으로 구성
- 모든 주요 화면과 버튼의 실제 이동·로딩·오류·재시도 상태
- Google Maps 브라우저 키와 Routes 서버 키의 로컬 환경 설정
- 비공개 GitHub 저장소 생성, 단계별 커밋과 최종 코드 업로드

이번 변경에서 제외한다.

- 실제 계명대학교 센서·행정 데이터 연결
- 로그인, 사용자별 차량 저장, 정기권 신청 쓰기 기능
- 관리자 대시보드
- Supabase 로컬 스택과 Docker
- 백그라운드 위치 추적이나 지속적인 경로 재계산

## Supabase 결정

이번 데모에서는 Supabase를 연결하지 않는다. 현재 저장·동기화할 실제 사용자 데이터가 없고, 로컬 Supabase는 Docker와 여러 서비스를 추가해 초기 요구사항인 가벼운 로컬 실행과 빠른 시연에 불리하다. 기존 `UniversityRepository`, `ParkingRepository`, `RecommendationRepository`, `VehicleRepository` 계약을 유지하므로 후속 단계에서 mock 구현만 Supabase 구현으로 교체할 수 있다.

이번 단계의 최소 백엔드는 Next.js Route Handler인 `/api/eta` 하나다. 이 경로는 Routes API 키를 서버 환경에서 읽고 외부 호출 결과를 앱에 필요한 작은 응답으로 정규화한다.

## 사용자 흐름

1. 홈에서 기본 목적지와 `현재 위치에서 지금 출발` 버튼을 본다.
2. 사용자가 목적지를 바꾸거나 기본 목적지를 유지하고 출발 버튼을 누른다.
3. 버튼은 `현재 위치 확인 중` 상태로 바뀌고 중복 클릭을 막는다.
4. 위치 권한이 허용되면 GPS 좌표를 `/api/eta`에 보낸다.
5. 서버는 Google Routes API의 `ComputeRoutes`를 호출해 교통을 반영한 자동차 이동시간과 거리를 구한다.
6. 위치 권한 거절, 시간 초과, Routes API 비활성화, 키 제한, 네트워크 실패가 발생하면 서버 또는 클라이언트가 계명대 인근 고정 출발지의 데모 추정값으로 전환한다.
7. 결과 화면은 `현재 위치 → 목적지`, `약 N분`, `HH:mm 도착`, `Google 교통 반영` 또는 `데모 추정` 출처를 보여준다.
8. 예상 도착 시각에 맞춘 학생 주차장 추천 3곳을 표시한다.
9. 추천 카드, 상세 정보, 지도, 내 정보, 다시 계산 버튼은 모두 실제 경로로 이동하거나 상태를 변경한다.

## ETA 아키텍처

### 클라이언트

`DepartureForm` Client Component가 목적지 선택, 위치 권한, 로딩 상태, 오류 상태를 담당한다. `navigator.geolocation.getCurrentPosition`에 합리적인 타임아웃을 적용하고 성공하면 원점 좌표를 서버에 전송한다. 권한이 거절되어도 흐름을 중단하지 않고 `useDemoOrigin: true`로 ETA API를 호출한다.

### 서버

`POST /api/eta` 요청:

```ts
type EtaRequest = {
  buildingId: string;
  origin?: { lat: number; lng: number };
  useDemoOrigin?: boolean;
};
```

성공 응답:

```ts
type EtaResponse = {
  buildingId: string;
  departureAt: string;
  arrivalAt: string;
  travelMinutes: number;
  distanceMeters: number;
  source: "google-routes" | "demo-estimate";
};
```

서버는 건물 ID를 테넌트 범위에서 검증한다. 좌표는 위도 `-90..90`, 경도 `-180..180` 범위를 검사한다. Google 요청에는 `travelMode: "DRIVE"`, `routingPreference: "TRAFFIC_AWARE"`를 사용하고 응답 필드는 `routes.duration,routes.distanceMeters`로 제한한다.

Google 응답이 없거나 요청이 실패하면 원점과 목적지의 직선거리에 도로 보정계수, 평균 도심 속도, 최소 이동시간을 적용해 안정적인 데모 ETA를 반환한다. 외부 API 오류 원문과 API 키는 클라이언트에 노출하지 않는다.

## 환경 변수

실제 값은 Git에서 제외되는 `.env.local`에만 둔다.

```dotenv
NEXT_PUBLIC_GOOGLE_MAPS_API_KEY=<browser-key>
NEXT_PUBLIC_GOOGLE_MAPS_MAP_ID=
GOOGLE_ROUTES_API_KEY=<server-key>
```

저장소의 `.env.example`에는 빈 값과 설명만 둔다. 사용자가 제공한 하나의 키를 로컬에서는 Maps JavaScript API와 Routes API 양쪽에 설정하되, Google Cloud 프로젝트에서 두 API를 활성화해야 한다. 배포 전에는 브라우저 키와 서버 키를 분리하고 HTTP 리퍼러/IP 또는 API 제한을 적용한다.

## 계명대학교 데모 데이터

### 목적지 건물

최소 10곳을 제공한다.

- 동산도서관
- 봉경관
- 바우어관
- 의양관
- 영암관
- 공학관
- 대명캠퍼스가 아닌 성서캠퍼스 본관
- 체육관
- 아담스채플
- 대운동장

모든 좌표는 데모용이며 실제 운영 좌표가 아님을 유지한다.

### 주차장

최소 8곳을 제공한다.

- 동문 학생주차장 — 학생, 핵심 추천
- 남문 학생주차장 — 학생, 핵심 추천
- 학생 제1주차장 — 학생
- 학생 제2주차장 — 학생
- 공학관 학생주차장 — 학생
- 대운동장 임시주차장 — 학생·행사
- 본관 주차장 — 교직원
- 중앙 주차장 — 교직원, 만차 사례

`ParkingLot`에 `accessType: "student" | "staff" | "shared"`를 추가한다. 학생 추천은 `student`와 `shared`만 포함한다. 본관·중앙 주차장은 지도와 전체 현황에는 표시하지만 학생 추천에서 제외한다.

### 목적지별 접근 데이터

고정된 `walkMinutes`와 `distanceMeters`만 쓰지 않고 `(parkingLotId, buildingId)`별 도보시간·거리를 가진 접근 매트릭스를 둔다. 동문 인근 건물은 동문 학생주차장이, 남문·공학관 인근 건물은 남문 또는 공학관 학생주차장이 우선하도록 한다.

### 시간대별 예측

각 주차장은 서로 다른 06·09·12·15·18·22시 잔여면 데이터를 가진다. 예상 도착 시각의 앞뒤 데이터 사이를 선형 보간하고 0과 정원 사이로 제한한다. 보간한 잔여면 비율로 `available`, `moderate`, `busy`, `full` 상태를 다시 계산한다. 추천 순위는 도착 시 잔여 비율, 목적지까지 도보시간, 예측 신뢰도를 함께 사용한다.

## 화면 설계

### 홈

- 도착 시간 입력을 제거한다.
- 목적지 선택과 현재 캠퍼스 현황을 우선 배치한다.
- 주 CTA를 `현재 위치에서 지금 출발`로 변경한다.
- 위치 아이콘, 로딩 텍스트, 데모 폴백 안내를 테두리 없는 채움형 표면으로 표시한다.

### 추천

- 시간 입력 없이 목적지 선택과 출발 버튼만 제공한다.
- 결과 상단에 이동시간, 예상 도착 시각, 거리, 계산 출처를 표시한다.
- 추천 카드에는 학생 이용 가능 여부와 도착 시 예상 잔여면을 표시한다.
- `다시 계산`은 입력 화면으로 돌아가거나 같은 목적지로 위치 계산을 다시 실행한다.

### 상세와 지도

- 상세 화면은 ETA 쿼리의 도착 시각을 사용한다.
- 지도는 API 키가 작동하면 실제 Google 지도를 표시한다.
- 키 제한 또는 지도 로딩 실패 시 기존 목록 대체 화면을 유지한다.
- 지도 목록의 모든 항목은 주차장 상세로 이동한다.

## 오류 처리

- 위치 권한 거절: 설명 후 데모 위치로 자동 계속
- 위치 시간 초과: 데모 위치로 자동 계속
- 잘못된 건물 ID: 400 응답과 폼 오류
- Routes API 비활성화·키 제한·과금 미설정: 데모 추정 응답
- 네트워크 단절: 오프라인 화면 또는 다시 시도 안내
- 중복 출발 클릭: 로딩 중 버튼 비활성화
- 예상 데이터 없음: 현재 잔여면을 사용하고 신뢰도를 낮춰 표시

## 테스트

- 시간대별 잔여면 선형 보간 테스트

## GitHub 저장소와 커밋

GitHub 계정 `hyidyong`에 비공개 저장소 `karmu`를 생성한다. `.env.local`, 빌드 결과, 의존성 디렉터리는 올리지 않는다. 설계, ETA 도메인, 계명대 데이터, 출발 UI, 지도·환경설정, 최종 검증 단위로 커밋한 뒤 기본 브랜치에 코드를 업로드한다.

## 완료 조건

- 사용자가 시간을 입력하지 않고 출발 버튼만으로 추천 결과에 도달한다.
- Google Routes가 가능하면 실제 도로 ETA가 표시된다.
- Google 호출이 실패해도 클릭 흐름이 끝까지 동작한다.
- 학생 추천에는 동문·남문을 포함한 학생 이용 가능 주차장만 나타난다.
- 건물 10곳 이상, 계명대 주차장 8곳 이상의 더미 데이터가 제공된다.
- 실제 키는 Git 이력에 포함되지 않는다.
- 테스트, 타입 검사, 린트, 프로덕션 빌드, 모바일 브라우저 QA가 통과한다.
