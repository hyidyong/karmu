# Karmu; PARK

> **출발 전에, 도착했을 때 주차할 수 있을지를 먼저 알려주는 캠퍼스 스마트 주차 PWA**

Karmu; PARK는 단순히 현재 주차장에 몇 자리가 남아 있는지를 보여주는 서비스가 아니라, **사용자의 현재 위치와 목적지를 기준으로 도착 예상 시각을 계산하고, 그 시점의 주차 가능성을 예측해 적절한 주차장을 추천하는 서비스**를 목표로 합니다.

계명대학교 성서캠퍼스를 데모 환경으로 사용했으며, 모바일 사용을 우선한 PWA 형태로 구현했습니다.

## Problem

대학 캠퍼스에서 차량으로 이동할 때 사용자가 실제로 궁금한 것은 단순한 ‘현재 빈자리 수’만이 아닙니다.

- 출발 시점에는 주차장이 비어 있어도 **도착할 때는 만차가 될 수 있음**
- 만차 여부를 모르고 캠퍼스에 진입하면 다른 주차장을 찾아 다시 이동해야 함
- 이 과정에서 교내 차량 동선이 길어지고 혼잡이 증가함
- 수업 직전에는 작은 주차 실패가 곧 지각으로 이어질 수 있음
- 주차장마다 목적지까지의 거리와 학생 이용 가능 여부가 다름

따라서 Karmu; PARK는 질문을 다음과 같이 바꿨습니다.

> **“지금 어디가 비어 있지?”가 아니라, “내가 도착할 때 어디에 주차하는 것이 가장 나을까?”**

---

## Solution

사용자가 목적지를 선택하면 Karmu가 다음 정보를 함께 계산합니다.

1. 현재 위치에서 목적지까지의 **예상 이동 시간(ETA)**
2. ETA를 기반으로 한 **예상 도착 시각**
3. 도착 시점 전후의 주차 추세를 반영한 **예상 잔여면 / 혼잡도**
4. 주차장에서 목적지까지의 **도보 거리**
5. 학생 이용 권한 등 **주차장 접근 조건**

이 정보를 종합해 사용자가 출발 전에 비교할 수 있도록 **상위 주차장 후보를 추천**합니다.

## Core Features

### 1. 도착 시점 기반 주차 예측

현재 잔여면만 보여주는 대신, 사용자가 실제 캠퍼스에 도착할 시각을 기준으로 주차 여유를 추정합니다.

현재 데모에서는 시간대별 Mock 데이터를 사용하고, 도착 시각 전후의 주차 추세를 보간해 예상 잔여면을 계산합니다.

### 2. 목적지 기반 주차장 추천

주차 가능성만 높다고 항상 좋은 주차장은 아닙니다.

Karmu는 다음 요소를 함께 비교합니다.

- 예상 잔여면
- 예상 혼잡도
- 목적지까지의 도보 거리
- 학생 이용 가능 여부
- 목적지별 접근성

이를 기반으로 상위 3개 주차장을 추천합니다.

### 3. Google Maps 기반 캠퍼스 지도

Google Maps JavaScript API를 연결해 캠퍼스 내 주차장 위치를 지도에서 확인할 수 있도록 구현했습니다.

- 주차장 8곳 마커 표시
- 모바일 환경을 고려한 지도 UX
- 지도 API가 동작하지 않는 경우에도 사용할 수 있는 목록 기반 fallback

### 4. Google Routes 기반 ETA 계산

`/api/eta` Route Handler에서 Google Routes API를 호출해 이동 시간을 계산합니다.

Routes API를 사용할 수 없는 환경에서는 데모가 중단되지 않도록 **결정적 fallback 계산**으로 전환됩니다.

### 5. 차량 등록 / 사용자 정보 흐름

학생 차량 등록 상태와 정기권 정보를 확인할 수 있는 프로필 흐름을 구성했습니다.

현재 MVP에서는 Mock 데이터지만, 향후 대학 차량 등록·승인 시스템과 연결할 수 있는 UX를 기준으로 설계했습니다.

### 6. 모바일 우선 PWA

모바일에서 바로 사용할 수 있는 캠퍼스 서비스라는 전제 아래 PWA 구조를 적용했습니다.

- Android Chrome: 앱 설치
- iPhone Safari: 홈 화면에 추가
- 프로덕션 환경에서 Service Worker 등록
- 오프라인 대응 화면 제공

## Demo Scope

계명대학교 성서캠퍼스를 기준으로 다음 데모 데이터를 구성했습니다.

- 목적지 건물 **10곳**
- 주차장 **8곳**
  - 동문 학생주차장
  - 남문 학생주차장
  - 제1학생주차장
  - 제2학생주차장
  - 공학관 학생주차장
  - 운동장 임시주차장
  - 본관 교직원주차장
  - 중앙 공용주차장
- 목적지별 접근성 및 도보 거리
- 도착 시각 기반 예상 잔여면
- 학생 이용 권한
- 차량 등록 및 신청 일정

발표 시나리오에서는 예를 들어 동산도서관 목적지에는 동문 학생주차장, 공학관 목적지에는 남문 학생주차장이 우선 추천되도록 구성했습니다.

> **현재 좌표, 잔여면, 예측값, 도보거리, 차량 정보 및 신청 일정은 모두 데모용 Mock 데이터이며 실제 계명대학교 운영 데이터가 아닙니다.**

## User Flow

```text
현재 위치 확인
      ↓
목적지 선택
      ↓
Google Routes API로 ETA 계산
      ↓
예상 도착 시각 산출
      ↓
도착 시점의 주차 여유 예측
      ↓
도보 거리 + 이용 권한 + 혼잡도 비교
      ↓
주차장 TOP 3 추천
      ↓
지도 / 상세 정보 확인
```

- 캠퍼스 주차 문제 정의 및 핵심 Pain Point 정리
- 관련 자료 및 뉴스 기사 조사
- 프로젝트 보고서 직접 작성

현장 발표에서는 프로젝트 구성과 발표에 대해 긍정적인 피드백을 받았습니다.

## Architecture

```text
src/
├─ app/
│  ├─ (student)/          # 홈, 추천, 지도, 주차장 상세, 프로필
│  ├─ api/eta/            # Google Routes API + fallback
│  └─ offline/            # 오프라인 대응
├─ components/
│  ├─ map/                # 지도 및 fallback UI
│  ├─ parking/            # 주차 상태 / 추천 카드
│  └─ recommendation/     # 출발 정보 / 추천 UX
├─ data/
│  ├─ contracts/          # 교체 가능한 repository 인터페이스
│  └─ mock/               # 계명대 데모 데이터
├─ domain/                # 대학, ETA, 주차장, 추천, 차량 타입
└─ lib/                   # ETA / 추천 / tenant 관련 로직
```

주요 데이터는 `universityId`, `campusId`, `parkingLotId` 단위로 분리해 특정 대학에 강하게 결합되지 않도록 구성했습니다.

현재 MVP에서는 영속 저장, 로그인, 실시간 구독이 필요하지 않아 Supabase나 별도 DB를 연결하지 않았습니다. 향후 실제 서비스 단계에서는 repository 구현을 교체하는 방식으로 백엔드를 확장할 수 있습니다.

## Google API Setup

Google Cloud 프로젝트에서 다음 API를 활성화합니다.

- Maps JavaScript API
- Routes API

```dotenv
# 브라우저에서 사용하는 지도 키
NEXT_PUBLIC_GOOGLE_MAPS_API_KEY=
NEXT_PUBLIC_GOOGLE_MAPS_MAP_ID=

# 서버의 /api/eta에서만 사용하는 경로 키
GOOGLE_ROUTES_API_KEY=
```

보안을 위해:

- `.env.local`은 Git에 포함하지 않습니다.
- `NEXT_PUBLIC_GOOGLE_MAPS_API_KEY`는 Maps JavaScript API와 허용 HTTP Referrer로 제한합니다.
- `GOOGLE_ROUTES_API_KEY`는 별도 서버 키로 만들고 Routes API 및 서버 호출 조건으로 제한합니다.
- Google Maps Platform은 사용량 기반 과금 서비스이므로 일일 할당량과 예산 알림을 설정하는 것을 권장합니다.

## Why Karmu; PARK

Karmu; PARK의 목표는 주차장을 보여주는 것이 아니라 **사용자가 출발 전에 더 나은 선택을 하도록 돕는 것**입니다.

현재 상태를 보여주는 정보 서비스에서 한 단계 더 나아가,

> **이동 시간 + 도착 시점의 주차 가능성 + 목적지 접근성**

을 함께 판단하는 캠퍼스 주차 의사결정 서비스를 빠르게 검증한 MVP입니다.
