# Karmu 모바일 주차 플랫폼 MVP 기반 설계

## 1. 목표와 범위

Karmu는 대학 주차 문제를 현장 도착 후의 탐색 문제가 아니라 출발 전의 예측과 선택 문제로 전환하는 모바일 웹앱이다. 첫 MVP는 계명대학교 성서캠퍼스를 기본 테넌트로 사용하지만, 데이터와 정책의 경계는 처음부터 여러 대학과 캠퍼스를 수용할 수 있게 둔다.

이번 기반 작업의 완료 범위는 다음과 같다.

- Next.js App Router와 TypeScript 기반의 모바일 전용 PWA 프로젝트
- 홈, 지도, 추천, 내 정보로 이어지는 학생용 앱 셸과 핵심 탐색 흐름
- Mock 데이터로 동작하는 캠퍼스, 건물, 주차장, 혼잡도, 차량 도메인
- Google Maps를 연결할 수 있는 지연 로딩 지도 모듈과 API 키 설정 안내
- 실제 백엔드로 교체 가능한 Repository 인터페이스와 테넌트 컨텍스트
- 반응형 모바일 레이아웃, 접근성, 성능 기준과 검증 명령

실시간 센서 수집, 예측 모델 학습, 실제 로그인, 차량 등록 승인, 결제, 관리자 대시보드는 후속 단계다. MVP에서는 해당 기능의 화면 및 데이터 경계를 보여주되 외부 시스템과 실제로 통신하지 않는다.

## 2. 설계 접근과 선택 이유

검토한 세 가지 접근은 대시보드 중심, 지도 중심, 목적 중심이다. 참고 이미지의 대시보드형 화면은 많은 정보를 한 번에 보여주지만 처음 방문한 사용자가 다음 행동을 결정하기 어렵다. 지도 중심 화면은 공간 파악에는 좋지만 도착 시간 예측과 목적지 기반 추천이라는 제품의 핵심 가치가 약해진다.

따라서 목적 중심 흐름을 채택한다. 홈에서 목적지와 도착 시간을 빠르게 입력하고, 추천 결과에서 상위 후보를 비교한 뒤, 상세 화면에서 근거를 확인하고 길찾기를 실행한다. 지도는 독립 탭으로 유지해 현재 현황을 탐색하는 보조 흐름을 담당한다.

## 3. 사용자 흐름과 화면 구조

### 핵심 흐름

1. 사용자가 홈에서 현재 캠퍼스와 전체 혼잡도를 확인한다.
2. `어디로 가시나요?`를 눌러 목적지 건물과 도착 예정 시각을 입력한다.
3. 시스템이 예상 잔여면, 목적지까지 도보 거리, 주차 성공 가능성으로 주차장 후보 세 곳을 정렬한다.
4. 사용자가 후보를 비교하고 한 곳을 선택한다.
5. 상세 화면에서 현재/도착 시점 잔여면, 시간대별 혼잡도, 운영시간, 이용 대상, 요금을 확인한다.
6. 하단 고정 행동 버튼으로 외부 길찾기 또는 지도 화면을 연다.

### 하단 내비게이션

- 홈: 캠퍼스 요약, 빠른 추천, 최근 목적지, 차량/정기권 알림
- 지도: 주차장 위치, 잔여면, 혼잡 상태, 목록과 지도 동기화
- 추천: 목적지/시간 입력과 추천 후보 비교
- 내 정보: 차량, 정기권, 신청 상태, 공지

하단 내비게이션은 안전 영역을 포함하고 화면 너비가 좁아도 네 항목이 잘리지 않게 한다. 추천은 제품 핵심 기능이지만 가운데 돌출 버튼처럼 장식하지 않고 동일한 구조 안에서 선택 상태만 강조한다.

### 홈 정보 우선순위

1. 캠퍼스 선택과 알림
2. 목적지 입력을 시작하는 주요 행동
3. 전체 혼잡도와 추천 가능 여부
4. 지금 가장 적합한 주차장 한 곳
5. 차량 등록 또는 정기권 마감 같은 행정 알림

## 4. 시각 시스템

계명대학교 공식 컬러 시스템을 기준으로 다음 토큰을 사용한다.

- Primary: KM BLUE `#034EA2`
- Critical accent: KM RED `#E23D3F`
- Ink: KM BLACK 기반의 짙은 중성색
- Surface: 흰색과 저채도 회색 단계

블루는 주요 행동, 현재 선택, 핵심 수치에만 사용한다. 레드는 만차, 오류, 신청 마감 임박처럼 즉시 주의가 필요한 상태에만 사용하며 다른 적색 변형을 추가하지 않는다. 여유/보통 상태는 새로운 강한 색을 늘리지 않고 중성 배경, 아이콘, 텍스트 라벨, 패턴 차이로 구분한다.

버튼에는 기본 테두리를 넣지 않는다. 카드와 입력도 선에 의존하지 않고 배경색, 간격, 아주 약한 그림자로 계층을 만든다. 키보드 포커스는 접근성을 위해 테두리 대신 외곽 포커스 링으로만 표시한다.

`--radius` 하나를 버튼, 카드, 입력, 시트, 알림, 배지에 공통 적용한다. 기본값은 16px이다. 지도 마커와 원형 아이콘 버튼처럼 의미 자체가 원형인 요소만 예외로 한다. 작은 배지는 반경을 바꾸지 않고 내부 여백과 높이만 줄인다.

타이포그래피는 별도 대용량 폰트 파일 없이 iOS와 Android의 시스템 한글 글꼴 스택을 사용한다. 숫자는 잔여면과 시간처럼 판단에 필요한 곳에서만 크게 보여준다. 아이콘은 Lucide의 필요한 아이콘만 사용하고 이모지는 기능 아이콘으로 사용하지 않는다.

## 5. 모바일 오토 레이아웃 원칙

- 지원 폭: 320px 이상 모바일 뷰포트
- 콘텐츠 최대 폭: 480px, 큰 화면에서는 중앙 정렬
- 높이: `100dvh`와 safe-area inset 사용
- 간격: CSS 변수 기반 4/8/12/16/24/32px 체계
- 터치 대상: 최소 44 x 44px
- 고정 CTA와 하단 내비게이션이 콘텐츠를 가리지 않도록 하단 패딩 계산
- 긴 건물명과 주차장명은 한글 줄바꿈 규칙과 말줄임 처리를 화면별로 구분
- 가로 스크롤은 후보 비교 영역처럼 의도된 곳에만 허용
- 키보드가 열린 상태에서 입력과 확인 버튼에 접근 가능하도록 스크롤 컨테이너 구성
- `prefers-reduced-motion`을 존중하고 애니메이션은 짧은 전환과 상태 피드백에만 사용

## 6. 프론트엔드 아키텍처

### 기술 선택

- Next.js App Router, TypeScript, React Server Components 우선
- Tailwind CSS와 최소한의 shadcn/ui 소스 컴포넌트
- 화면 전역 CSS 변수로 색상, 반경, 간격 관리
- 서버 상태 라이브러리와 전역 상태 라이브러리는 초기 MVP에서 제외
- 폼 상태는 로컬 React 상태, URL 검색 파라미터, Server Component props로 제한
- 차트 라이브러리 없이 경량 SVG 또는 CSS로 혼잡도 추이를 표시

### 제안 디렉터리

```text
src/

    map/

```

각 기능 컴포넌트는 표현과 상호작용만 담당하고, Mock 데이터 선택과 추천 계산은 도메인/데이터 계층에 둔다. 페이지는 필요한 데이터만 조합한다. 클라이언트 컴포넌트는 입력, 지도, 하단 시트처럼 브라우저 상태가 필요한 경계에만 사용한다.

## 7. 다대학 데이터 경계

모든 대학 종속 엔터티는 다음 키 체계를 따른다.

- `universityId`
- `campusId`
- `buildingId`
- `parkingLotId`
- `parkingZoneId`

주차장, 운영시간, 요금, 이용 대상, 등록 정책, 학사/행사 일정은 반드시 `universityId` 또는 그 하위 캠퍼스에 귀속된다. UI는 테넌트 이름이나 색상을 하드코딩하지 않고 `UniversityBrand` 설정을 읽는다. 계명대학교 색상은 첫 테넌트의 설정값이다.

데이터 접근은 `ParkingRepository`, `RecommendationRepository`, `VehicleRepository`, `UniversityRepository` 인터페이스 뒤에 둔다. 초기 구현은 `Mock*Repository`를 사용한다. 실제 API 또는 Supabase를 붙일 때 페이지와 컴포넌트를 바꾸지 않고 구현체와 인증 컨텍스트만 교체한다.

## 8. 추천 데이터 흐름

1. 사용자가 `buildingId`와 `arrivalAt`을 입력한다.
2. 현재 `universityId`와 `campusId`가 요청 컨텍스트에 포함된다.
3. Repository가 해당 테넌트의 주차장 후보와 현재/예상 잔여면을 반환한다.
4. 추천 도메인이 예상 잔여면, 도보 거리, 이용 가능 정책, 신뢰도를 점수화한다.
5. 화면은 상위 세 곳과 `가깝고 여유 있음`, `도착 시 24면 예상` 같은 사람이 이해할 수 있는 추천 근거를 표시한다.

Mock 추천 점수는 설명 가능한 규칙 기반으로 구현한다. 예측 모델이 도입되면 동일한 출력 계약을 유지하면서 추천 Repository의 구현만 교체한다.

## 9. Google Maps 통합

제공된 ZIP은 Google Maps Platform 101 React Codel랩의 starter/solution이며 다음 코드를 재사용할 수 있다.

- `@vis.gl/react-google-maps`의 `APIProvider`, `Map`, `AdvancedMarker`, `Pin`
- `@googlemaps/markerclusterer`를 이용한 마커 클러스터링 패턴
- 지도 클릭, 카메라 이동, 원 오버레이 수명주기 패턴

샘플은 Vite와 React 18 구조이므로 앱 파일을 그대로 복사하지 않는다. 라이선스 고지를 유지하면서 Next.js용 `CampusMap` 클라이언트 컴포넌트로 필요한 패턴만 옮긴다. 지도 컴포넌트는 해당 화면에 진입할 때만 `next/dynamic`으로 불러오며 서버 렌더링에서는 지도 스켈레톤을 제공한다.

API 키는 `NEXT_PUBLIC_GOOGLE_MAPS_API_KEY` 환경변수로 주입한다. 저장소에는 `.env.example`만 커밋하고 실제 키는 커밋하지 않는다. Google Cloud Console에서 HTTP referrer 제한과 Maps JavaScript API 제한을 설정해야 한다. 키가 없거나 로딩이 실패하면 앱 전체가 깨지지 않고 주차장 목록 대체 화면과 설정 안내를 표시한다.

초기 Mock 지도 중심점은 계명대학교 성서캠퍼스로 두되, 실제 주차장 좌표는 검증된 데이터를 받기 전까지 명확히 Mock으로 표시한다.

## 10. PWA와 오프라인 경계

`manifest.ts`, 앱 아이콘, 테마 색상, standalone 표시 모드를 구성한다. 작은 서비스 워커를 등록해 정적 앱 셸과 오프라인 안내만 제공한다. 실시간 잔여면과 지도 타일은 오래된 데이터를 사실처럼 보여주지 않도록 오프라인 캐시 대상으로 삼지 않는다.

오프라인에서는 마지막 조회 시각과 연결 끊김을 명확히 표시하고, 추천 실행과 길찾기처럼 최신 데이터가 필요한 행동을 비활성화한다.

## 11. 성능 원칙

- 홈 초기 화면에는 Google Maps와 지도 SDK를 포함하지 않는다.
- 지도, 고급 시각화, 후속 관리자 기능은 라우트 단위로 분할한다.
- 클라이언트 컴포넌트를 작은 상호작용 경계로 제한한다.
- 대형 UI/차트/상태관리 라이브러리를 추가하지 않는다.
- 이미지가 필요하면 Next Image와 정확한 크기를 사용하고, 장식 이미지는 최소화한다.
- 아이콘과 컴포넌트는 필요한 항목만 추가한다.
- 독립 데이터 요청은 병렬로 시작하고 불필요한 워터폴을 만들지 않는다.
- 인라인 스타일은 지도 SDK가 런타임 좌표/크기를 요구하는 제한된 경우 외에는 사용하지 않는다.

## 12. 오류와 상태 처리

- 지도 API 키 없음/로드 실패: 지도 대신 목록과 설정 안내
- 위치 권한 거부: 선택 캠퍼스 중심으로 동작하며 권한 재요청을 강제하지 않음
- 데이터 없음: 빈 화면 대신 다음 행동이 있는 Empty State
- 추천 후보 없음: 이용 정책 또는 운영시간 때문에 제외된 이유 표시
- 오프라인: 마지막 갱신 시각과 연결 상태 표시
- 예측 신뢰도 낮음: 단정적인 표현 대신 범위와 대체 후보 표시
- 잘못된 테넌트/주차장 ID: 사용자용 Not Found 화면

오류는 토스트만으로 사라지게 두지 않고 사용자가 복구 행동을 취할 수 있는 화면 상태로 표현한다.

## 13. 접근성 및 검증

- 색상만으로 혼잡 상태를 전달하지 않고 텍스트 라벨과 아이콘을 병행한다.
- 포커스 순서, 스크린리더 레이블, 폼 오류 연결을 확인한다.
- 본문과 버튼은 WCAG AA 대비를 충족한다.
- 최소 폭 320px, 대표 iPhone/Android 폭, 모바일 가로 회전을 점검한다.
- iOS Safari와 Android Chrome의 safe area, 주소창 높이 변화, 키보드 노출을 확인한다.
- 정적 검사, TypeScript, 프로덕션 빌드를 완료 기준으로 삼는다.
- 지도 API 키가 없는 상태와 있는 상태를 모두 검증한다.

## 14. 초기 완료 기준

- 바탕화면의 `karmu` 저장소에서 개발 서버와 프로덕션 빌드가 실행된다.
- 네 개 주요 탭과 추천-상세 핵심 흐름을 Mock 데이터로 탐색할 수 있다.
- 모든 기본 버튼은 무테이며 주요 표면의 반경이 동일한 토큰을 사용한다.
- 계명대학교 공식 블루와 단일 레드 강조색이 CSS 변수로 관리된다.
- 320px부터 480px 이상까지 콘텐츠 잘림과 의도하지 않은 가로 스크롤이 없다.
- 앱 설치에 필요한 manifest, 아이콘, service worker가 존재한다.
- Google Maps 키가 없어도 대체 UI가 동작하고 키가 있으면 지도 모듈을 연결할 수 있다.
- 다대학 식별자와 Repository 계약이 UI 바깥 데이터 계층에 존재한다.
